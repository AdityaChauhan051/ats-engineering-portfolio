01 / About ATS

Engineering depth.
Manufacturing reality.

An electronics engineering partner built for the full product journey.

ATS Design & Innovation is a technology-driven company engaged in electronics product design, PCB development, embedded systems, IoT solutions and electronics manufacturing services (EMS). We build innovative, cost-effective and reliable electronic solutions for diverse industries, with a special focus on audio mantra products and smart bell solutions.

Our engineering work spans medical devices, tracking devices, BLE sensor systems and cloud-connected IoT prototypes. Wherever the product sits, the discipline is the same: clear requirements, documented interfaces, verified hardware and firmware, and a clean handover.

From a first proof of concept to bulk production, we stay accountable for the details that decide whether a product performs in the field — not just in the lab.

CASE STUDY 01
MedicalBLESecurity

Insulin Pump Firmware & Security

Embedded firmware engineering in a regulated medical-device context, with emphasis on reliable MCU firmware, BLE connectivity, peripheral integration and security mechanisms.

Platform / Hardware

STM32L496ZG / STM32L4 development platform; X-NUCLEO-BNRG2A1 BLE expansion board using BlueNRG-2; ST-LINK V3 for programming and debug.

Interfaces / Protocols

Embedded C/C++, BLE, SPI, I2C, UART, ADC, DAC, timers/PWM; AES-CCM, SHA-256, HMAC-SHA256, PBKDF2-HMAC-SHA256.

Engineering work
  • Developed and debugged STM32 firmware using STM32CubeIDE and STM32 HAL/LL drivers.
  • Integrated BlueNRG-2 BLE and mobile-side testing with ST BLE Toolbox; worked on pairing, provisioning, privacy-related behaviour and secure communication concepts.
  • Implemented and integrated cryptographic building blocks with the STM32 cmox library, including AES-CCM, SHA-256 and HMAC operations; used PBKDF2 with SHA-256 for key derivation and authentication-related flows.
  • Peripheral driver development and board-level integration for sensors and interfaces.
  • Worked within a quality and compliance-oriented development environment, with exposure to IEC 62304, ISO 13485:2016 and IEC 60601-1-8 documentation expectations.
Relevant to

Secure device onboarding, encrypted wireless communication, firmware architecture, peripheral integration, traceable development practices and security-conscious product engineering.

Scope note: Reflects embedded engineering contributions and technology exposure; it does not claim certification of a complete product or independent regulatory approval.
CASE STUDY 02
BLESensorsProvisioning

BLE Device Provisioning & Sensor Integration

BLE-enabled device development and sensor interfacing across STM32 evaluation platforms, including provisioning, configuration and acquisition of environmental and system data.

Platform / Hardware

STM32L496ZG on NUCLEO-L496ZG; BlueNRG-2 on X-NUCLEO-BNRG2A1; STM32WB55 and STM32U585 evaluation exposure; SHT40 temperature/humidity sensor, TMP107 temperature sensor, ADS1115 four-channel ADC, W25Q128FW / AT25Q128A external flash, NHD-1.69-160128UGC3 OLED display.

Interfaces / Protocols

BLE, I2C, SPI, UART, ADC, GPIO and timer interfaces.

Engineering work
  • Integrated BLE modules with STM32 firmware and tested device discovery/provisioning workflows.
  • Developed sensor interfacing for temperature, humidity and multi-channel ADC acquisition.
  • Worked on external flash driver integration and non-volatile data handling.
  • Integrated OLED display hardware and embedded display data paths.
  • Performed peripheral debugging, communication validation and firmware bring-up.
Relevant to

Security sensor integration, local status display, device configuration, event logging and reliable communication between a hub and peripheral modules.

CASE STUDY 03
IoTCloudOTA

ESP32 Cloud OTA & Device Control

Connected-device prototypes exploring remote control, cloud-hosted firmware delivery and over-the-air update workflows.

Platform / Hardware

ESP32-C6 development module and ESP32 camera-module development hardware; WS2812 addressable RGB LED; Wi-Fi; power and GPIO interfaces.

Interfaces / Protocols

Wi-Fi, MQTT using PubSubClient, Blynk IoT platform, HTTP/HTTPS, AWS S3 presigned URLs and a Node.js/Express backend.

Engineering work
  • Built an IoT control prototype using Blynk and MQTT for remote RGB LED control; used MQTT Explorer for broker/device connectivity troubleshooting.
  • Developed a Node.js/Express web service concept to list firmware binaries and initiate OTA updates.
  • Integrated AWS S3 presigned URL workflows for controlled firmware download.
  • Investigated OTA download failures, HTTP response errors and timeout behaviour.
  • Worked with ESP32-C6 GPIO and WS2812 LED control.
Relevant to

Cloud-to-device workflows, remote configuration, OTA update orchestration, Wi-Fi connectivity and connected-device troubleshooting.

Scope note: These are prototype and integration activities, not a claim of a production-scale cloud platform or a certified OTA security implementation.

Proposed work packages

Six workstreams, one integrated system.

A

Product definition & architecture

Confirm use cases, device count, radio protocols, operating environment, power targets, security model, regulatory markets and production constraints. Produce a system block diagram, interface definition and development plan.

B

Hardware & PCB engineering

Evaluate ARM compute platforms and connectivity modules; define memory and storage; design power input, battery charging and backup; integrate wired and wireless interfaces; prepare schematics, PCB layout, BOM and prototype test plan.

C

Embedded Linux & hub firmware

Establish board support and boot flow; configure the Linux image and required services; implement hardware interfaces, device communication, provisioning, event handling, local diagnostics, logging and update mechanisms.

D

Security-device integration

Define onboarding and supervision flows for sensors and actuators; implement pairing, device identity, health monitoring, tamper reporting, alarm prioritisation, lost-link handling and recovery behaviour.

E

Mobile & cloud integration

Define secure APIs and event flows for user accounts, hub registration, remote control, notifications, history and device management. Finalise mobile and backend scope with the client.

F

Security, verification & handover

Develop a threat-informed security plan covering identity, authenticated communication, secure boot/update capabilities where supported, key handling, access control and data protection. Execute functional and integration tests; deliver source, design files and manufacturing documentation.

1

Discovery

Requirements, use cases, constraints, system architecture and risk register.

2

Proof of concept

Platform and radio evaluation; early hub-to-device communication demonstration.

3

Engineering prototypes

PCB prototypes, Linux/firmware baseline, device integration and initial app/cloud interfaces.

4

Integrated system

End-to-end alarm flows, remote control, notifications, diagnostics and security hardening.

5

Verification & handover

System testing, issue closure, manufacturing package, source code and technical documentation.

Recommended first step: a paid discovery and architecture phase, followed by milestone-based prototype development and system validation. This reduces platform and integration risk before committing to the full production design.

07 / Delivery & Handover

Yours to own, build and extend.

Good engineering is more than working hardware. It is documented interfaces, reproducible builds and a package your team can own, maintain and manufacture.

Handover-ready by design

The expected package for an agreed scope typically includes:

  • System architecture, interface specifications and configuration records.
  • Schematics, PCB source/layout files, Gerbers, BOM and assembly notes, where included in scope.
  • Firmware and application source code, build instructions, dependency versions and release notes.
  • Linux configuration/build materials and deployment instructions for the selected platform.
  • API definitions, cloud deployment documentation and database/interface descriptions, as applicable.
  • Test plans, test reports, known-issues register and prototype verification results.
  • Manufacturing and service documentation, programming instructions and handover support.

How we work

A disciplined, transparent process from the first conversation to production.

  • Requirements before code. We clarify the product, constraints and acceptance criteria before committing to a design.
  • Risk reduction first. Platform and radio feasibility is validated before full development begins.
  • Milestone-based delivery. Each phase has clear outputs, so progress is visible and reviewable.
  • Documented interfaces. Version-controlled source, reproducible builds and release notes are part of the work.
  • Long-term partnership. Support continues beyond prototype delivery, through production and field issues.
